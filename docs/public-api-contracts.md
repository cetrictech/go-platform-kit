# Public API contracts

This document is normative for all exported symbols in the ten releasable modules listed in the [compatibility matrix](compatibility-matrix.md). It covers exported functions, methods, interfaces, constants, variables, configuration fields and returned resources. Package comments provide local details; the more specific contract below applies when it narrows a general rule. `internal/` and `integration/` are not supported consumer APIs. No released version exists yet; these contracts establish the first release baseline, not a retrospective v1 guarantee.

## Rules applying to every export

- Configure values before publishing them to other goroutines. Unless explicitly described as concurrent below, mutable structs, maps, slices, options, rule registries and returned stream/session objects are caller-synchronized. Do not mutate a supplied configuration, callback state, TLS configuration, error details or payload concurrently with an operation reading it. A getter returning a map/slice is not a synchronization boundary unless documented as a copy.
- Pure/value operations may run concurrently with independent inputs and destinations. A destination pointer belongs to that invocation. Exported constants, sentinel error identities and immutable configuration data may be read concurrently; callers must never reassign exported sentinel variables. SDK synchronization does not make arbitrary application values thread-safe.
- Pass a non-nil context wherever accepted. Per-operation contexts control that operation, not a reusable client's entire lifetime, unless a constructor explicitly creates a context-owned worker. Cancellation is cooperative and may have an unknown remote outcome after a request is sent. A method without context is synchronous and has no promise of cancellation or bounded completion. Supply finite operation/shutdown deadlines; never assume `Close()` can interrupt an arbitrary callback.
- The creator owns a resource until it explicitly transfers ownership. Close resources returned by constructors, rows, response bodies, statements, subscriptions and native bridges in their documented order. Stop admitting work, cancel/drain active operations, close dependent resources, then close their parent client. A `Native` or underlying-field escape hatch borrows the resource; it does not transfer ownership or authorize a second independent close.
- Callbacks, custom serializers, transports, providers, validators, log writers and observers remain application-owned. They may be invoked concurrently according to the owning component's concurrency model. They must honor contexts where supplied, avoid blocking without a bound, and synchronize captured mutable data. Do not recursively invoke a lifecycle operation from its own callback. Panic recovery exists only where explicitly documented; callbacks must not rely on a process-wide recovery mechanism.
- Limits bound accepted work or wire size at the documented boundary. They are not an operating-system memory quota: input values, callbacks, driver buffers and retained application objects can still consume memory. Configure queue, pool, body, token, batch and timeout bounds for the deployment, and use [performance and resource checks](performance.md) before increasing them.
- Public interfaces are implementer contracts. Adding a method to an interface breaks external implementations even when callers still compile. Prefer separate optional interfaces. Public struct-field removal/type changes, JSON field changes, error-code changes, default changes affecting behavior, ownership changes and newly required validation are compatibility changes even if a source checker cannot detect them.

## Root module API families

All import paths below begin with `github.com/cetrictech/go-platform-kit/`.

| `config`: Load, Validate, getters, Dump, Options | Independent destinations may be loaded concurrently; a destination and its input readers are exclusive to one load | Synchronous conversion/validation; custom readers/validators must be bounded; Load assigns only after successful validation | Caller owns readers and destination; secret-safe dumps are diagnostic snapshots, not a credential store |
| `database`: Rows, Row, Scan, JSON, hooks/events | Each row stream, row handle and destination has one owner; JSON values are mutable; callbacks may run concurrently for concurrent queries | Scan is bounded by rows/driver and caller closing them; hooks have the supplied operation ctx and must return promptly | Scan does not take parent-client ownership; caller closes Rows; JSON and event values must not be mutated concurrently |
| `encodingx`: Serializer, JSON, Raw, Error | Built-in stateless codecs may be shared with frozen config; separate decode destinations | Synchronous encoding with configured byte checks; custom codec implementation determines CPU/cancellation behavior | Returned bytes belong to caller; custom serializer retained by an adapter must be safe for concurrent calls |
| `errors`: AppError, options, constructors, classifiers, Is/As/Unwrap | Construct/mutate before sharing; read only afterward; Classify may return an existing AppError | Synchronous classification only; Retryable is metadata, not permission to retry a non-idempotent action | Details, Metadata and Cause remain caller-approved data; Error() is diagnostic and is not a public response contract |
| `health`: Registry, Check, Run, Handler, dependency helpers | Register and Run are concurrent; set Timeout and OnResult before serving | Run bounds each check; one stuck callback retains one invocation slot and later runs report busy; hooks must still cooperate | Registry owns invocation coordination, not dependency clients; handler exposes safe status, never raw dependency causes |
| `httpx/client`: Client, Config, Do/JSON, file helpers, StatusError | Share configured clients; each request/body, response body and download writer has one owner | Request ctx controls transport/retry waits; retries require explicit idempotency, permitted methods and replayable bodies; cancellation after send may be ambiguous | Close Do response bodies; JSON closes its own response; injected client/transport/writer remain caller-owned; Close only releases owned idle transport resources |
| `httpx/middleware`: constructors and handlers | Built handlers can serve concurrently if injected state is safe; response writers are request-scoped | Request ctx propagates; admission/authentication callbacks must honor it; middleware cannot terminate context-ignoring handlers | The enclosing server owns listener/request lifecycle; middleware does not take injected registry/limiter/logger ownership |

## Driver boundaries and review

Core `database.Rows`/`Row`, `encodingx.Serializer`, clock, idempotency and Kafka interfaces remain small and driver-free. Normal PostgreSQL/MySQL/Kafka operations return SDK-owned records or standard-library types. Root imports must not pull optional infrastructure modules into a consumer graph; `scripts/check-independent.sh` and the clean-consumer check enforce the module boundary.

The following public native integration surfaces are intentional and must be reviewed as compatibility obligations: PostgreSQL `Native`, transaction `Native`, SQLDB/statement bridges; MySQL Native/statement access; Redis native client, pipeline/WATCH callbacks and type aliases (`PoolStats`, `ScoredMember`, `Stream`, `StreamMessage`, `Pending`); Kafka native tuning/client access; gRPC transport/interceptor/protobuf types; SPIFFE native SVID source integration; OpenTelemetry provider/exporter interfaces. Their dependency upgrades require both SDK and native-driver API compatibility review. Borrowing does not transfer close ownership. Prefer an existing SDK operation or a small consumer-owned interface before adding another native type to public signatures.

Before approving a new export, the reviewer must identify its concurrency mode, context/outcome behavior, ownership/cleanup, bounds, error/wire contract, and entry in this document. The API baseline/compatibility check is necessary but does not establish those behavioral properties. Run the contract tests as part of `scripts/release-check.sh`; every exception must have a migration record and the version increment described in [versioning](versioning.md).


Resource-bound fixes in the stability safeguards make MySQL's zero MaxOpenConnections
select a finite default of 32; explicit idle counts must not exceed the open bound.
Redis PoolSize is a hard command/pipeline bound per node (zero selects
10*GOMAXPROCS); pipelines share that pool. Pub/Sub connections are separate and
must be bounded and closed by applications. Worker cancellation discards queued
jobs without invoking them, reports cancellation, accounts Failed and Completed
without Started, and releases queued/registered closures after workers terminate.
